# kream-reresell

KREAM 랭킹 상품을 훑어서, 빠른배송 수요가 충분하고 마진이 나는 상품에
**일반배송(창고 보관) 구매 입찰**을 자동으로 넣고, 이미 넣은 입찰 중 기준에 못 미치게 된 것을 자동으로 지우는 프로그램.

## 판단 규칙

1. 랭킹 → 상품군(기본 `가방`, 여러 개면 준 순서대로) → 순위대로 상품을 본다.
   상품군은 랭킹 탭에 있는 21개 전부 고를 수 있다 (신발·러닝화·부츠 포함).
   신발/러닝화/부츠는 사이즈 옵션이 있는 상품이 대부분이라 그 상품은 아래 "옵션이 있는 상품" 규칙으로 건너뛴다.
2. 상품 페이지 "거래 내역 더보기" 에서 **최근 30일 빠른배송(⚡) 체결 건수** 를 센다. 15건 미만이면 건너뛴다.
3. 구매하기 모달에서 **빠른배송 가격 = A** (내가 팔 예상가, 95점 가격은 무시).
4. 일반배송 → "즉시 구매 / 구매 입찰" → 구매 페이지의 **즉시 판매가 = B**.
5. `A - B > A × 최소 마진율` 일 때만 입찰. 최소 마진율은 **A 금액 구간별**로 다르게 둘 수 있다
   (예: A 0~50,000원 10%, 50,000~100,000원 11%, 100,000원 이상 12%). A 가 어느 구간에도 없으면 건너뛴다.
   **상품 금액 상한**을 두면 (예: 300,000원) A 가 그 금액을 넘는 상품은 B 도 읽지 않고 바로 건너뛴다. 비워두면 제한 없음.
6. 구매 입찰 탭에서 희망가 **B**, 마감기한 **7일**, 구매 입찰 계속.
7. 배송방법 **창고 보관** (선택 확인이 안 되면 절대 진행하지 않음), 포인트 있으면 최대 사용, 결제 카드는 그대로.
8. 입찰하기 → 확인 항목 3개 체크 → 입찰하기 → "구매 입찰이 완료되었습니다" 확인 → 탭 닫기.

**입찰 기준(금액 구간별 마진율, 상품 금액 상한)은 GUI 의 [입찰 기준] 표에서 바꾼다** - `data/bid_rules.json` 에 저장되고
명령행 실행도 같은 파일을 읽는다. 파일이 없으면 `.env` 의 `MIN_MARGIN_RATE` 하나로 된 구간 하나(상한 없음)를 쓴다.
나머지 숫자(30일 / 15건 / 7일 / 상품 수)는 `.env` 에서 바꾼다.

건너뛰는 경우: 체결 거래 표가 없는 상품(아직 리셀 거래가 열리지 않음 - 매 실행마다 다시 확인한다),
옵션(사이즈)이 있는 상품, 빠른배송 판매자가 없는 상품, 이미 입찰한 상품(`data/bids.json`),
**마이페이지 구매 입찰 탭에 지금 입찰 중인 상품** (실행 시작 때 목록을 읽는다. 목록 API 에 상품 ID 가 없어서
`data/bids.json` 기록과 상품명·희망가가 같으면 그 ID 를 쓰고, 없는 입찰만 상세를 열어 API 응답으로 읽는다 - 하나에 1~2초).

속도: 이미지/동영상/폰트를 받지 않는다(`.env` `BLOCK_IMAGES=0` 으로 끌 수 있다). 상품 하나에 약 10초.

## 입찰취소 규칙

마이페이지 > 구매 내역 > **구매 입찰** 탭(`/my/buying?tab=bidding`)에 살아 있는 입찰을 화면 순서대로 본다.

1. 입찰 상세(`/my/buying/입찰번호`)에서 상품 ID · 희망가 · 마감을 읽는다 (`api/m/bids/입찰번호` 응답).
2. 그 상품을 **다시 처음부터 입찰한다고 생각하고** 위 판단 규칙 2~5 를 똑같이 적용한다
   (최근 30일 빠른배송 건수, A, B, `A - B > A × 구간별 최소 마진율`). 거래량이 모자라도 A/B 까지 읽어 보고서에 남긴다.
   상품 금액 상한은 새로 입찰할 때만 쓰는 규칙이라 이미 넣은 입찰을 다시 판정할 때는 쓰지 않는다.
3. 기준에 못 미치면 상세 화면의 **입찰 지우기** → 확인창 [입찰 지우기]. `DELETE api/m/bids/입찰번호` 가 204 로 끝나야 지운 것으로 본다.
   다 끝난 뒤 목록을 다시 읽어 정말 사라졌는지 확인하고, 남아 있으면 "확인필요" 로 표시한다.
4. 조건을 충족하면 그대로 둔다(입찰유지). 판단할 수 없으면(상품 페이지 오류, 빠른배송 가격을 못 읽음 등) **지우지 않고** "확인필요".
5. 지운 상품은 `data/bids.json` 에서도 빼서, 나중에 조건이 다시 맞으면 새로 입찰할 수 있게 한다.

희망가는 최소 2만원, 천원 단위 (2026-09-04 실측). 취소 전용 조건은 따로 없고 입찰 기준(`data/bid_rules.json`, `.env`)을 그대로 쓴다.

## 설치

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
```

브라우저는 설치된 크롬을 그대로 쓴다 (`auth/chrome_profile_kream` 프로필). headless 는 봇 탐지에 걸리기 쉬워 쓰지 않고,
대신 크롬 창을 모니터 바깥으로 옮겨 둔 채 실행한다 (작업표시줄에만 크롬 아이콘이 남고, 다른 작업을 방해하지 않는다).
창을 보며 확인하려면 `--show-chrome` 또는 `.env` 의 `SHOW_CHROME=1`, GUI 에서는 [크롬 창 보기] 체크 (실행 중에도 바꿀 수 있다).
로그인은 프로필에 유지되고, 세션이 끊기면 `.env` 의 `KREAM_ID`/`KREAM_PW` 로 이메일 자동 재로그인한다
(`/login/email` 폼, 캡차 없음 - 2026-09-03 확인). 비밀번호를 비워두거나 자동 로그인이 실패하면 크롬 창을 화면으로
불러와 직접 로그인할 때까지 5분 기다리고, 로그인되면 다시 치운다.

## 실행

```
.venv\Scripts\python scripts\run.py --category 가방 --dry-run     # 판단만 (입찰 안 함)
.venv\Scripts\python scripts\run.py --category 가방               # 조건 맞으면 실제 입찰
.venv\Scripts\python scripts\run.py --category 가방 --limit 10
.venv\Scripts\python scripts\run.py --category 가방 지갑 신발 --dry-run   # 여러 상품군을 준 순서대로
.venv\Scripts\python scripts\run.py --all-categories --dry-run           # 랭킹의 모든 상품군을 칩 순서대로
.venv\Scripts\python scripts\run.py --list-categories                    # 상품군 이름 목록
.venv\Scripts\python scripts\run.py --product 385408 --force --stop-before-submit --inspect
```

- `--category 이름 [이름 ...]` : 상품군. 여러 개면 준 순서대로 하나씩 랭킹을 열어 처리한다. `--limit` 은 상품군마다 적용.
- `--all-categories` : 랭킹 탭의 상품군 21개를 칩 순서대로 전부 돈다.
- `--dry-run` : 거래량/마진 판단까지만 하고 입찰 폼은 건드리지 않는다.
- `--stop-before-submit` : 입찰 화면을 다 채우되 마지막 "입찰하기" 는 누르지 않는다.
- `--force` : 거래량/마진 조건을 무시한다 (화면 점검용).
- `--inspect` : 화면마다 `dumps/` 에 스크린샷 + 접근성 트리를 남긴다.
- `--product ID ...` : 랭킹 대신 지정한 상품만 본다.

입찰취소:

```
.venv\Scripts\python scripts\cancel.py --dry-run              # 판단만 (지우지 않음)
.venv\Scripts\python scripts\cancel.py                        # 기준 미달 입찰을 실제로 지움
.venv\Scripts\python scripts\cancel.py --stop-before-submit   # 확인창의 [입찰 지우기] 직전에 멈춤 (점검용)
```

판매 내역 정리 ([내역] 과 같음):

```
.venv\Scripts\python scripts\history.py --month 8               # 8월 (8월이 아직 안 지났으면 작년 8월)
.venv\Scripts\python scripts\history.py --month 8 --year 2026 --open
```

## 판매 내역 정리 규칙 ([내역])

달을 고르면 **보관 판매 > 종료** 의 판매 중 **보관 상세의 "거래일시"** 가 그 달인 것을 모아, 건마다 **구매 내역 > 종료** 에서
매입 건을 찾아 짝짓고 정산 시트 모양의 엑셀로 저장한다 (`바탕화면\KREAM 내역 YYYY-MM.xlsx`, 같은 파일이 열려 있으면 시각을 붙여 저장).

화면을 하나씩 열지 않고 그 화면이 부르는 API 를 페이지 안에서 그대로 불러 읽는다 (2026-09-04 실측, 판매 47건에 10초쯤).

- 보관 판매(`api/seller/inventory/items/finished?status=payout_completed`): 보관번호 `id`, 보관판매 주문번호 `oid`(I-SW…),
  판매가, 정산금액(`price_breakdown.total_payout`), **거래일시(`transaction.date_created` = 보관 상세의 거래일시)**, 정산일, 제품코드(`style_code`), 상품명 한/영, 사이즈.
  팔렸지만 아직 정산 전인 것(보관 중 > 판매완료)도 같은 달이면 넣고 `비고` 에 "정산 전" 이라고 적는다.
- 구매 내역(`api/o/bids/?tab=finished`): 결제번호 헤더의 일시(= 주문 화면의 "거래 일시" = **매입 일시**) 와 상품 줄의 입찰번호,
  그리고 **창고보관 링크의 보관번호** (`/my/inventory?…&id=보관번호`). 이 보관번호가 보관 판매의 `id` 와 같아서 매입-판매를 정확히 잇는다.
- 짝이 된 구매의 상세(`api/m/bids/입찰번호`)에서 **매입 주문번호 `oid`(B-SW…)** 와 **매입가(`price_breakdown.total_price` = 즉시 구매가 + 수수료 등, 실제 결제금액)** 를 읽는다.
  매입가는 **항상 수수료 포함** (원본 시트의 레고 포드 GT 줄 114,600원 = 111,000 + 수수료 3,600 과 같은 기준, 2026-09-04 확인).

짝 맞추는 순서: ① 보관번호 → ② 창고보관 링크가 없는 구매는 상세의 `keep.ask_id` 로 보관번호 확인 →
③ 그래도 없으면 상품명·사이즈가 같고 판매보다 먼저 결제된 가장 오래된 구매. 끝내 못 찾으면 매입 열을 비우고 노란 줄로 표시한다
(KREAM 에서 사지 않고 [보유 상품 추가] 로 보관에 넣은 상품이 여기에 해당한다).

엑셀 열은 정산 시트와 같다: `# | 매입 주문번호 | 제품코드 | 제품이름 (한/영) | 사이즈 | 매입 일시 | 매입가 | 보관판매 주문번호 | 판매 일시 | 정산가 | 수익 | 메모`
+ 맨 오른쪽 `비고`(정산 상태, 짝 맞춘 방법). 수익 = `정산가 − 매입가`, 메모 = `수익 × 0.3` 수식이고 아래에 합계 줄이 있다. 거래일시 오름차순(1일 → 말일).

## 바탕화면에서 실행

바탕화면의 **`KREAM 자동입찰`** 바로가기를 더블클릭하면 창(`scripts/gui.pyw`)이 뜬다.
상품군 목록(랭킹 탭의 21개 전부)에서 원하는 것을 체크하고, 상품군마다 볼 상품 수·모드(실제 실행 / 판단만)를
고른 뒤 [입찰]. 체크한 상품군을 나열된 순서(랭킹 칩 순서)대로 하나씩 돌며, 결과는 엑셀 보고서 하나에 모인다
(`상품군` 열, 요약 시트에 상품군별 판정 수). [전체 선택]/[전체 해제] 버튼이 있다.

**[입찰 기준]** 표: 줄마다 `A 부터(원)` / `A 미만(원, 비우면 끝없음)` / `최소 마진율(%)`. [구간 추가]로 줄을 늘리고
(새 줄의 "부터" 는 앞 줄의 "미만" 으로 채워진다) [삭제]로 지운다. 구간이 겹치면 실행하지 않고 알려준다.
아래 `상품 금액 상한: A 가 __원을 넘으면 바로 건너뜀` 에 금액을 넣으면 (예: 300000) 그보다 비싼 상품은 쳐다보지 않는다 (비우면 제한 없음).
[입찰]/[입찰취소]를 누를 때 자동으로 `data/bid_rules.json` 에 저장되고, [기준 저장]만 눌러도 저장된다.
[입찰취소]를 누르면 마이페이지 구매 입찰 목록을 순서대로 다시 판정해 기준 미달 입찰을 지운다
(상품군·상품 수는 쓰지 않고, 모드가 "판단만" 이면 지우지 않고 "취소대상" 으로만 표시).
[내역]을 누르면 연도·달을 고르는 창이 뜨고(기본은 지난달) [실행] → 확인을 거쳐 그 달의 판매 내역을
`바탕화면\KREAM 내역 YYYY-MM.xlsx` 로 저장한다 (위 "판매 내역 정리 규칙"). 끝나면 [이번 보고서 열기]로 바로 열 수 있다.
크롬은 화면 밖에서 돌아가고 진행 상황은 이 창에만 표시된다. [크롬 창 보기]를 켜면 실행 중에도 크롬 창을 불러올 수 있다
(끄면 다시 치운다). [중지]를 누르면 지금 보는 상품(입찰)까지만 처리하고 멈춘다.
끝나면 결과 요약과 보고서 경로를 알려준다.

상품군 이름과 `category_filter` 값은 `src/kream_reresell/ranking.py` 의 `CATEGORY_IDS` 에 있다 (2026-09-04 실측).
값이 바뀌어 엉뚱한 상품군이 열리면 프로그램이 알아채고 칩을 직접 눌러 맞춘다.

## 결과

- **엑셀 보고서**: `바탕화면\KREAM 결과\KREAM 입찰결과 YYYY-MM-DD HHMM.xlsx` - 실행이 끝나면 저장된다 (자동으로 열지 않음, `--open` 을 주면 연다).
  상품마다 상품군, 판정(입찰완료/입찰대상/건너뜀/중단/오류/확인필요), 사유, 30일 빠른배송 건수, A, B, A−B, 마진율,
  기준마진(그 상품의 A 금액 구간에 적용된 최소 마진율), 입찰가, 링크.
  저장 위치를 바꾸려면 `.env` 에 `REPORT_DIR=경로`.
- 입찰취소 보고서는 `KREAM 입찰취소결과 YYYY-MM-DD HHMM.xlsx`. 순위 열은 구매 입찰 목록에서의 순서,
  판정은 입찰취소 / 취소대상(dry-run) / 입찰유지 / 확인필요 / 오류, 입찰가 열은 그 입찰의 희망가.
- 판매 내역([내역])은 `바탕화면\KREAM 내역 YYYY-MM.xlsx` (정산 시트 모양, 위 "판매 내역 정리 규칙"). 로그는 `logs/history_*.log` / `logs/gui_*.log`.
- `data/bids.json` : 입찰한 상품 (같은 상품에 다시 입찰하지 않는다). 입찰취소로 지운 상품은 여기서 빠진다.
  체결되거나 기한이 지나 사라진 입찰은 자동으로 빠지지 않으니, 그 상품에 다시 입찰하려면 직접 지운다.
- `data/run_log.csv` : 본 상품마다 거래량 / A / B / 결과 (누적)
- `logs/run_*.log` / `logs/cancel_*.log` / `logs/gui_*.log` : 실행 로그
- 프로그램이 중간에 죽어 보고서가 안 만들어졌으면 `python scripts/report_from_log.py` 로 마지막 실행분을 엑셀로 만든다.
